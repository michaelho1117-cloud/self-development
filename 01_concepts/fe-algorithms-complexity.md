# Concept: アルゴリズムと計算量の直感（探索・整列）

- **Track:** FE
- **Roadmap item:** `00_roadmap/next-topics.md` #1 · FE syllabus テクノロジ系 / 基礎理論 — アルゴリズム（探索, 整列, 計算量）
- **Status:** lab-verified
- **Created:** 2026-11-08

## Goal

線形探索・二分探索と代表的な整列の**狙い**を説明でき、入力サイズ *n* に対して「だいたい何倍遅くなるか」を **O記法の直感**で見積もれる。

## Core ideas

### 1. アルゴリズム = 「正しい手順」＋「どれだけ重い手順か」

正しさだけでは足りない。FE では **同じ問題を解く別手順の比較**（探索の仕方、並べ替えの仕方）と、**計算量（おおまかなコスト）** がセットで出る。

Feynman 一言: *「答えが出る手順」ではなく「*n* が増えたとき何が爆発するか」を見る。*

### 2. 計算量の直感（ビッグオーの「階」）

試験で最初に押さえる階（小さいほど速いイメージ）:

| 階 | 読み方の直感 | *n* が 10→1000 になったときの感覚 |
|----|--------------|-----------------------------------|
| O(1) | サイズにほぼ無関係 | ほぼ変わらない |
| O(log *n*) | 半分に折っていく | ほんの少し増える |
| O(*n*) | 要素をだいたい一通り見る | 約 100 倍 |
| O(*n* log *n*) | 「一通り」×「折り回数」 | 約 100×少し |
| O(*n*²) | 二重ループ級 | 約 10,000 倍 |

- 定数倍や低次の項は試験の「直感比較」では後回し。まず **階が違うか** を見る。
- 「最悪」「平均」を問われたら、問題文の条件（すでに整列済みか、等）を読む。

### 3. 探索（search）

**線形探索（linear search）**

- 先頭から順に比べる。見つかるまで／最後まで。
- 整列不要。最悪おおよそ **O(*n*)**。
- 「どこにあるか分からない名簿を上から読む」イメージ。

**二分探索（binary search）**

- **あらかじめ昇順（または降順）に整列済み**であることが前提。
- 中央を見て、左半分か右半分かを捨てる → 候補がだいたい半分。
- 最悪おおよそ **O(log *n*)**。
- 前提を忘れるとバグ（または試験のひっかけ）になる。

対比の一言: *線形は「探す」、二分は「折って捨てる」。捨てる権利はソート済みがくれる。*

### 4. 整列（sort）の直感（実装暗記より「性格」）

FE では手順の細部より、**比較回数のオーダー感**と「安定か／追加メモリか」のラベルが効く。

| 系統の例 | 粗いオーダー感 | 覚え方 |
|----------|----------------|--------|
| 単純交換・選択・挿入など | だいたい **O(*n*²)** 級になりやすい | 二重ループで隣や最小を探す |
| マージソートなど分割統治 | **O(*n* log *n*)** | 半分に分けてからマージ |
| クイックソート | 平均 **O(*n* log *n*)**、最悪は悪くなり得る | 枢軸で分ける（偏りに注意） |

- 「どれが一番速いか」一択ではなく、**入力の性質・安定性・メモリ**で選ぶ話もある。まずはオーダーの地図を持つ。
- 探索の前提として「整列しておくコスト」と「その後の高速探索」をセットで考える。

### 5. 見積もりの手順（試験用チェックリスト）

1. 入力サイズの記号は何か（*n* = 件数？キー長？）。
2. ループは一重か、入れ子か、毎回半分になるか。
3. 事前条件（ソート済みか）を満たすコストは問題に含まれるか。
4. 答えは「手順の名前」か「オーダー」か「向く場面」か。

## Why it matters (exam / practice)

- テクノロジ系の定番。用語穴埋めだけでなく、「この条件なら線形／二分のどちらか」「*n* が倍になるとどうなるか」が出る。
- データ構造カード（配列の添字アクセス、スタック／キュー）と直結する次の語彙層。
- 実務でも「全件スキャンで足りるか／索引やソートが要るか」の初手判断と同じ筋肉。

## Common confusions

- **二分探索を未整列配列に使う** — 半分捨てる根拠がない。先にソートするか、線形に落とす。
- **O(*n*) と O(*n*²) を体感で区別できない** — 「一重 vs 二重」で紙にループを書いてから選ぶ。
- **「クイックは常に最速」信仰** — 平均と最悪、枢軸の偏りを分けて覚える。
- **log を「小さいから無視」** — O(*n*) と O(*n* log *n*) は別階。巨大 *n* では差が出るが、O(*n*²) ほど劇的ではない、という位置づけ。

## Socratic checks (fill after claiming understanding)

1. **Why not X?** 毎回の問い合わせの前に配列をソートしてから二分探索する方針は、問い合わせが **1 回だけ**のとき、線形探索より速いか。なぜ（またはなぜそうとは限らないか）。
2. **Edge case / first principles?** 要素数 1、またはキーが存在しないとき、線形と二分はそれぞれどう終了するか。空配列では何を返すべきか。
